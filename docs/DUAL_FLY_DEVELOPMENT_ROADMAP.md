## 0. 결론과 개발 원칙

**권고:** 두 마리를 한 번에 구현하지 말고 **Fly-Code(의사코드→Python)부터** 만든 뒤 **Fly-NL(자연어→의사코드)**을 추가한다. 두 마리는 동일한 FlyWire 연결 그래프의 **독립 실행 인스턴스**로 시작한다. 해부학적 연결은 같더라도 시냅스 상태·학습 이력·체크포인트는 분리한다. 이것은 실제 생물학적 초파리 두 마리를 재현했다는 뜻이 아니다.

핵심 성공 조건은 '정답을 외운다'가 아니라 다음을 모두 만족하는 것이다.

1. **변환 선택의 출처가 실제 그래프 내 뉴런 활동과 시냅스 상태**임을 로그로 입증한다.
2. **보상 또는 오차에 따라 그래프의 허용된 시냅스 상태가 변화**하고, 재시작 후에도 보존된다.
3. 기존 예문이 아닌 **새로운 변수·상수·문장 표현·알고리즘 조합**에서 정답률을 측정한다.
4. 신경망을 제거하거나 연결을 섞으면 성능이 어떻게 달라지는지 **대조 실험**한다.
5. 결과 코드가 문법적으로만 올바른 게 아니라 **다양한 입력에서 요구 동작**을 수행하는지 검사한다.

### 0.1 '오직 파리의 시냅스'의 정확한 경계

| 구성 | 허용 | 금지하거나 생성 경로에서 제거 |
| --- | --- | --- |
| 언어 이해 | Fly-NL의 신경 활동·시냅스 학습 | 정규표현식으로 의도 분류, 외부 언어 모델, 외부 단어 임베딩, 사전 기반 의도 결정 |
| 의사코드 선택 | Fly-NL이 중간 표현의 토큰·구조·인자를 예측 | 사람이 작성한 질문→완성 의사코드 템플릿 대입 |
| Python 선택 | Fly-Code가 문법 토큰·식·블록·복사 위치를 예측 | 의사코드를 고정 Python 템플릿으로 치환하는 실질적인 번역기 |
| 인코딩·디코딩 | UTF-8/바이트를 고정된 입력 뉴런 자극으로 인코딩, 출력 뉴런 활동을 고정 규칙으로 토큰화 | 고정 어휘 뜻풀이, 가중치가 학습되는 외부 NLP/분류기 |
| 학습 관리 | 정답 데이터, 오류 신호 계산, 시냅스 업데이트 명령, 체크포인트·로그 | 모델의 답을 사람이 작성한 규칙으로 몰래 수정 |
| 검증 | Python AST/컴파일·테스트·격리 실행·정답 비교 | 검증기가 잘못된 알고리즘을 새로운 정답 코드로 대신 생성 |

**물리적으로 불가능한 오해 방지:** 문자 입출력, 평가기, 저장장치까지 '생물학적 시냅스만으로' 구성할 수는 없다. 이 연구에서 '시냅스만'은 **의미 판단과 다음 출력 선택에 관여하는 학습 가능한 계산이 FlyWire 그래프 안에 있다**는 뜻으로 운영 정의한다. 고정 입출력 부호화와 검증용 계산은 별도로 존재해야 한다.

**중요:** 연결 지도(connectome)는 뉴런과 시냅스의 배선 자료이며, 그 자체가 훈련된 언어 모델도, 발화 시간과 막전위를 완전히 설명하는 생물물리 모델도 아니다. 아래 신경 동역학·학습법은 추가 **가정**으로서 독립 검증해야 한다.

README에 기록된 기존 실험 성과: 문법 평가 **144/144**, 확장된 Python 사용 예제 **100과/300개**, 알고리즘 표현 변형 평가 **56/56**, 추가 빈칸 평가 **7~10/12**. 이 값들은 **기존 하이브리드 시스템의 소규모 평가 결과**이지 두 신경망의 독립적 언어 이해·범용 코딩 능력을 증명하지 않는다.

### 1.1 현재 구조에서 목표를 가로막는 직접적인 지점

1. **fly.py / Fly.propagate()**: 특징 해시를 입력 축에 놓고 연결을 한 번 합산한다. 전체 뉴런의 시간 변화, 반복 전파, 장기 문맥·시냅스 업데이트가 없다.
2. **reward.py / RewardMemory**: 기억은 샘플별 scores에 저장된다. 학습 후 FlyWire 시냅스 배열이 변하는지 추적할 수 없다.
3. **algorithm_model.py / AlgorithmModel.embed()**: 출력은 FlyWire 활성보다 일반 어휘 특징의 비중이 큰 혼합 벡터다.
4. **goal_model.py / parse_goal()**: 자연어를 정규식으로 미리 해석한다. 파리 A를 도입하면 이 부분이 생성 경로에서 사라져야 한다.
5. **program_model.py / OPERATIONS, render()**: 정답 코드의 형태를 사람이 지정한다. 파리 B가 '선택'하는 범위가 제한된다.
6. **pseudocode.py / translate()**: 고정 번역기로서 유용하지만 최종 파리 전용 생성 경로에서는 **검증기나 비교 기준**으로만 남겨야 한다.
7. **goal_model.py / solve()**: 지원하지 않는 요청을 Qwen에 전달한다. 생성 모델 선택 규칙을 엄격하게 분리하지 않으면 결과가 오염된다.
8. **test_goal.py**: 특정 범위의 합 요청에서 단순히 그 정답 수만 반환해도 정답으로 인정될 수 있다. **문제 일반화 테스트**와 다른 입력 검증이 필요하다.

## 2. 제안 아키텍처

~~~text
사용자 자연어
    │
    ▼
[고정 UTF-8/바이트 인코더 + 위치/경계 자극]
    │
    ▼
[Fly-NL: FlyWire 연결망 인스턴스 A]
  - 반복적 뉴런 상태
  - 학습되는 허용 시냅스 강도
  - 의사코드 토큰과 복사 위치 출력
    │
    ▼
[IR 검사: 형태·블록·인자 수만 검증, 답을 작성하지 않음]
    │
    ▼
구조화 중간 언어(IR)
    │
    ▼
[고정 IR 인코더]
    │
    ▼
[Fly-Code: FlyWire 연결망 인스턴스 B]
  - 독립 시냅스/상태/체크포인트
  - Python 코드 토큰과 복사 위치 출력
    │
    ▼
[고정 출력 토큰 결합기]
    │
    ▼
[Python AST 검사 + 격리된 실행/테스트]
    │
    ├── 통과 → 코드, 근거, 점수
    └── 실패 → 오류 유형/보상 신호 → A/B 학습 또는 제한된 재시도
~~~

### 2.1 두 마리의 분리 조건

- **Fly-NL(A)**: 자연어→IR. 출력: IR 토큰 시퀀스 및 해당 원문 span 복사/인자 참조. 학습 신호: 정답 IR의 토큰 오류, 구조 오류, 실제 의미 오류.
- **Fly-Code(B)**: IR→Python. 출력: Python 토큰 시퀀스와 복사 span. 학습 신호: 정답 코드 토큰, 문법 오류, 실행 테스트 결과.
- 같은 연결 그래프를 사용해도 **학습 상태는 A와 B가 공유하지 않는다**. 학습/평가 데이터, 가중치 파일, 난수 시드, 오류 기록을 독립적으로 저장한다.
- 먼저 **정답 IR을 B에 입력**하여 B만 평가한다. 다음에 **정답 IR로 A를 평가**하고, 마지막에 **A 예측 IR→B**를 종단 평가한다.
- 그래프가 작아서 출력 어휘를 한 번에 충분히 표현할 수 없으면 **시간에 따라 여러 출력 비트를 인코딩**하는 결정적 디코더를 검토한다. 디코더 자체는 문맥을 해석하지 않아야 한다.

### 2.2 IR(중간 언어)을 먼저 동결할 것

자연어와 Python 사이에서 자유로운 한국어 문장을 쓰지 말고 **작은, 문법이 명확한 IR**을 만든다. 아래 예시는 **새 표준 제안**이며 현재 구현된 명령 문법이 아니다.

~~~text
FUNC sum_even
LET total 0
FOR i RANGE 1 11
  IF EQ (MOD i 2) 0
    ADD total i
  END
END
RETURN total
END_FUNC
~~~

위 예시의 RANGE는 **시작 포함·끝 제외**로 정의한다. 따라서 1부터 10까지의 짝수를 합산한다. 자연어의 '까지' 해석은 A가 결정해야 한다. B가 임의로 보정해서는 안 된다.

IR 사양에 반드시 포함할 것:

- 표준 토큰: FUNC, LET, FOR, IF, ELSE, RETURN, CALL, ADD, END 등 **최소 집합**부터.
- 표현식: 리터럴, 변수 참조, 비교, 사칙연산, 범위, 리스트.
- 블록: INDENT/DEDENT 대신 명시적 END 계열 또는 구문 트리 선택. 중첩 제한과 종료 조건 정의.
- 이름/숫자/문자열: **COPY(span_start, span_end)** 또는 바이트 토큰 출력으로 새로운 이름·값을 처리. 어떤 span을 복사할지는 신경망이 결정.
- 의미 규칙: FOR의 범위 포함 여부, RETURN과 PRINT 차이, 변수 유효 범위, 연산자 우선순위.
- 오류: 불완전 IR은 **invalid_ir**로 표시. 규칙이 누락된 의미를 추측해서 채우지 않는다.
- IR 버전: dataset, checkpoint, 평가 기록에 버전과 해시를 고정한다.

### 2.3 입출력 설계: 언어 의미를 몰래 넣지 않기

**입력 인코더**는 UTF-8 바이트, 시작/끝 구분, 위치, 현재 출력 접두사, 이전 예측 결과 등만 결정적으로 인코딩한다. 기존의 정규식, 언어별 사전, 사전학습 임베딩을 **의미 해석**에 쓰지 않는다.

**출력 디코더**는 신경 활동으로부터 고정된 뉴런 그룹/시간 슬롯의 점수를 읽어 다음 토큰과 선택한 복사 위치를 만든다. **동의어 해석, 구문 자동 완성, 변수명 발명**은 하지 않는다.

주의: 임의 바이트를 고정 뉴런에 연결하는 것만으로 언어의 의미가 생기지 않는다. 긴 문맥, 한국어 조사, 중첩 조건, 미지의 변수명은 큰 병목이 될 수 있다. 사전 정의한 핵심 어휘에서 시작해 점진적으로 확장한다.

## 3. 신경 엔진의 설계·검증

### 3.1 그래프 형식

- FlyWire CSV의 **실제 root ID, 방향(pre→post), syn_count** 보존.
- 모든 뉴런에 **일관된 단일 인덱스** 부여. 현재 fly.py의 입력용 sources와 출력용 targets 분리 구조를 반복적 신경 시뮬레이션용 공통 인덱스로 변경.
- sparse CSR/CSC 인접 구조로 변환. 같은 연결의 집계, 자기 연결·중복 처리 정책을 명시.
- **원본 구조 해시, 선택 뉴런 ID 목록, 필터 임계값, 원본 데이터 버전**을 메타데이터로 저장.
- 기존 시냅스가 아닌 연결을 임의로 추가하지 않는다. 원본 syn_count는 초기 강도에 사용할 수 있지만 **생리학적 시냅스 효능과 동일하다고 가정하지 않는다**.
- 신경전달물질에 따른 흥분/억제 정보가 없으면 **임의 부호 가정의 민감도 실험**을 별도로 진행한다.

### 3.2 시간에 따른 신경 상태

MVP는 단순한 시간 이산 모델로 출발한다. 예를 들어 입력 전류, 누출, 임계값, 불응 상태, 반복 전달을 구현한다. **생물학적으로 검증된 완전 뇌 시뮬레이터라는 주장을 하지 않는다.**

~~~text
for each time step:
    apply fixed encoded stimulus to designated input neurons
    accumulate weighted spikes over ORIGINAL directed edges
    update membrane-like state with leakage and threshold
    emit spikes / rate observations at designated readout neurons
    update eligible synapses only during learning
~~~

- 첫 검증은 64~256 뉴런의 작은 실제 부분 연결망에서 실시.
- 다음 512 → 2,048 → 더 큰 그래프 순으로 확장. 데이터 선정과 연결 보존 비율을 기록.
- 반복적 전파 시 고립 뉴런, 입력→출력 경로 부재, 포화 발화, 침묵 발화, 수치 불안정 검사.
- 같은 입력+가중치+시드로 **결과를 재현**해야 한다.
- Python 프로토타입은 작게 시작하고 대규모 그래프는 **희소 연산 또는 C++ 커널**로 최적화한다. 속도 향상 전/후 결과 일치 테스트 필요.

### 3.3 시냅스 학습 (핵심 미구현 요소)

**학습되는 값은 FlyWire가 허용한 기존 간선의 시냅스 강도/가소성 상태**여야 한다. 예문→정답 사전, 외부 분류기 계수, 별도 Transformer 가중치가 정답을 저장해서는 안 된다.

권장 실험 경로:

1. **학습 가능성 확인:** 작은 출력 어휘(예: 4개 동작)의 입력-출력 분류가 가능한지 검증.
2. **후보 업데이트 규칙:** STDP + 보상 조절(3요인 학습) 또는 **기존 간선에만 적용하는 감독 오차 기반 업데이트**를 비교한다. 둘 다 가설적 구현이며 생물학적 재현 정도는 별도 표시한다.
3. **적격성 흔적(eligibility trace):** 뉴런의 선행 활동을 시냅스별로 기록해 나중에 도착한 보상이 선택 원인과 연결되도록 한다.
4. **정규화·제한:** 가중치 상·하한, 희소성, 부호 제한, 폭주 방지, 장기 안정성 검증.
5. **체크포인트:** A/B별 weights, 신경 상태(필요 시), step, 시드, IR/데이터 버전, 그래프 해시 저장.
6. **가중치 불변 대조군:** 같은 초기 시냅스 상태에서 학습 업데이트를 끈 frozen 모델과 비교.

**필수 증거:** 학습 이전/이후 시냅스 해시가 학습 모델에서는 변경되고 frozen 모델에서는 변경되지 않아야 한다. 하지만 **해시 변경 자체는 학습 성공의 증거가 아니며**, 보지 못한 데이터의 성능 개선을 추가로 보여야 한다.

### 3.4 출력 시퀀스 학습

- 정답 다음 토큰을 제공하는 **teacher forcing**과 실제 생성에서 자신의 앞선 출력을 다시 입력하는 **자기회귀 추론**을 구분한다.
- BOS/EOS, 구문 경계, 가변 길이, 최대 토큰 수, 시간 단계/토큰, 타임아웃, 중단 조건 정의.
- 훈련에는 정답 토큰 오차를, 최종 평가에는 **전체 프로그램 완성률·실행 정답률**을 사용.
- 출력이 문법에 맞지 않으면 학습 피드백으로 보내되, 파이썬 작성기를 이용해 대신 교정하지 않는다.
- 분기·반복 구조가 길어질수록 문맥 보존이 어려우므로 **장기 문맥 실험**을 별도로 설계.

## 4. 구현 순서: 의존성과 완료 기준

각 단계에서 **코드, 데이터, 테스트, 재현 가능한 결과 보고서**를 남긴다. 아래 순서를 건너뛰면 모델 외부 규칙의 기여와 시냅스 기여를 구분하기 어렵다.

### P0. 기준선 고정 및 연구 계약 (최우선)

**구현:**
- 기존 README의 수치와 실행 조건을 문서화하되 독립 실험과 구별.
- 현재 모델 실행 경로를 **legacy**로 명명하고 새 fly-only 경로와 명시적으로 분리.
- 결정론적 데이터 분할(train/validation/test), 시드, 코드 버전, 그래프 파일 해시 저장.
- 명세서에서 'FlyWire 기반 특징 추출'과 '학습 가능한 신경 시냅스 모델'을 서로 다른 개념으로 표시.
- 테스트 명령 **python -m unittest -v**, **python benchmark.py**를 프로젝트 기본 확인 대상으로 지정. 실제 결과는 실행 환경에서 별도 기록.
- 새 경로에서 Qwen API 호출이 발생하면 실패하는 차단 테스트 작성.

**완료 기준:** 기준선 보고서, 잠긴 평가 데이터, 현재/새 경로 구분, 모델 호출 금지 테스트가 존재한다.

### P1. 그래프 공통 인덱스 및 반복 시뮬레이터

**구현:**
- FlyWire CSV 검증기와 단일 뉴런-ID 인덱스 생성.
- 기존 간선 수·방향·syn_count 합계 보존 검증.
- 시간 상태와 반복 전파 구현, 입출력 뉴런 그룹 지정, 결정적 인코딩.
- 무입력, 동일 입력, 파손된 CSV, 고립 그래프 테스트.
- 원본 그래프와 변형 그래프를 공정하게 비교할 실험 설정 저장.

**완료 기준:** 동일 시드로 발화열 동일, 불변 그래프 해시 확인, 작은 그래프에서 반복 활동과 읽기 가능한 출력 검증.

### P2. 시냅스 가소성 및 체크포인트

**구현:**
- 하나의 간단한 보상/감독 학습 규칙을 실제 간선 강도에 적용.
- 업데이트 허용 간선 목록과 초기 가중치 보존.
- 학습→저장→재시작→같은 입력 추론 테스트.
- 학습률, 보상 크기, 포화 조건과 weight-delta 분포 기록.

**완료 기준:** **toy task**에서 frozen보다 학습 모델이 개선되는 반복 실험, 가중치 변화와 재현성 증거. 실패한다면 P3로 넘어가지 않고 신경 엔진 재검토.

### P3. Fly-Code MVP (먼저 완성할 파리)

**범위:** 정답 IR 입력 → Python 생성. 먼저 LET, PRINT, ADD, IF, FOR, FUNCTION, RETURN, END 정도만. 처음에는 숫자와 단순 식부터 시작.

**구현:**
- IR 문법 및 정답 코드 쌍 생성(수작업 또는 검증 가능한 비-AI 데이터 생성기).
- 입력 IR의 토큰·문맥을 자극으로 변환.
- Fly-Code가 Python 토큰/복사 위치를 순차 예측하도록 학습.
- 생성한 코드에 대해 compile, AST, 격리 실행 및 변형 입력 테스트.
- 변수 이름, 숫자, 반복 범위를 **학습 사례와 다르게** 만든 평가 세트 사용.

**완료 기준(초기 목표, 미달성 시 원인 분석):**
- 제한된 20~30개 유형의 숨긴 테스트에서 문법 통과율 **≥90%**.
- 그중 실행 가능한 코드의 의미 정답률이 **≥80%**인지 측정(목표이지 예상 성능 아님).
- 출력 선택 과정의 뉴런/시냅스 근거를 기록. 고정 번역기로 코드 생성하지 않음.

### P4. Fly-NL MVP (두 번째 파리)

**범위:** 짧은 한국어/영어 명령 → 같은 IR. 별도의 정규식 의도 분류 금지.

**구현:**
- 동일 의도를 여러 문장으로 표현한 자연어↔IR 학습 쌍.
- 단어 순서 바꾸기, 조사/동의 표현, 처음 보는 식별자·숫자, 복합 조건을 **의도별로 분리**해 평가.
- 이름과 수치를 복사할 위치 예측 기능.
- 의사코드의 트리/명령/인자/블록까지 맞는지 검사.
- '모르겠다/불완전'을 출력할 수 있게 하여 근거 없는 코드 생성을 줄인다.

**완료 기준:** 정답 IR의 토큰·구조·의미 평가를 분리해 보고. 학습 문장과 의미적으로 겹치는 문장만 맞히는 상태를 성공으로 취급하지 않음.

### P5. 종단 연결 및 코드 검사

**구현:**
- Fly-NL 예측 IR → 검증 → Fly-Code → Python 실행 결과.
- A 실패와 B 실패를 **정답 IR을 이용한 진단 실험**으로 분리.
- 컴파일 통과, 예제 테스트, 숨긴 테스트, 경계 사례, 시간 제한을 구분.
- 실패 유형을 A의 의미 오류, IR 형식 오류, B의 Python 문법 오류, 실행 오류, 결과 오류로 나눔.
- 검증기는 자동으로 정답 코드를 끼워 넣거나 외부 모델로 재작성하지 않음.

**완료 기준:** 원본 자연어 하나에서 최종 코드까지 재현 가능한 추적 ID, 두 파리의 독립 로그, 테스트 결과가 모두 연결됨.

### P6. 실패 피드백과 제한된 재시도

**구현:**
- 단순 syntax penalty보다 **어떤 입력·검증에서 틀렸는지** 구조화된 보상 신호 제공.
- B의 로컬 오류와 A의 의도 오류를 분리해 해당 파리에만 책임을 부여할 수 있는 감독 평가.
- 종단 테스트 성공 여부만 주는 약한 보상 방식과 단계별 감독 방식 비교.
- 한도(예: 최대 3회)를 정한 재생성. 이전 실패를 신경 입력으로 제공하되 수정 선택은 파리가 담당.

**완료 기준:** 동일 조건에서 단회 생성 대비 재시도 후 성공률 증가를 확인. 단순히 더 많은 시도를 해서 얻은 향상과 **학습 자체의 향상**을 구분.

### P7. 진짜 FlyWire 효과를 검증하는 대조 실험

동일 데이터/출력 어휘/학습 예산/시드 정책으로 다음을 비교:

| 실험군 | 목적 |
| --- | --- |
| 실제 FlyWire 연결망 + 학습 시냅스 | 제안 모델 |
| 실제 FlyWire 연결망 + 가중치 고정 | 가소성 효과 |
| 같은 뉴런 수·간선 수·정도 분포를 최대한 맞춘 재연결 그래프 | 실제 배선 구조 효과 |
| 단순 무작위 그래프 | 그래프 일반 효과 |
| FlyWire 출력 제외(전달 제거/자극만) | 우회 경로 및 데이터 누출 감시 |
| 두 파리 A→B vs 한 파리 자연어→Python | 단계 분리의 이득/오류 누적 |
| 정답 IR→B vs A의 예측 IR→B | A의 오류가 B에 전파되는 영향 |

- 무작위 시드 **최소 5개**를 초기 기준으로 잡고 평균·표준편차·신뢰구간 보고.
- 동일 데이터의 문장만 바꾼 평가 외에 **알고리즘 계열 자체를 홀드아웃**한 평가.
- 성능뿐 아니라 학습 시간, CPU/RAM, 추론 지연, 파라미터/시냅스 수 기록.
- 결과가 무작위 그래프와 비슷하거나 더 나쁘면 **그 사실을 그대로 결과로 기록**한다.

**완료 기준:** FlyWire 실험군의 구조적 기여 여부를 과장 없이 말할 수 있고, 데이터 누출 및 비교 조건이 명시됨.

### P8. 대시보드·문서·배포 정리

- A/B 각각 학습 단계, 입력 자극, 활성 뉴런, 변한 시냅스 수, 출력 토큰, 검증 결과를 시각화.
- 기존 데모와 신규 실험 화면을 분리, '시뮬레이션'과 '실제 초파리 활동 측정'을 혼동하지 않도록 표시.
- 로컬에서 안전하게 실행되는 훈련/추론/평가 명령 정리.
- 자동 테스트·성능 회귀 체크·데이터 라이선스 고지·재현 문서화.

## 6. 데이터셋과 평가 설계

### 6.1 단계별 데이터셋

| 데이터 | 입력 | 정답 | 핵심 검증 |
| --- | --- | --- | --- |
| B-기초 | 정답 IR | Python 토큰 | 출력·대입·연산 |
| B-제어 | 정답 IR | Python 토큰 | 함수·조건·중첩 반복 |
| A-기초 | 한 문장 자연어 | 정답 IR | 목적·인자 해석 |
| A-변형 | 같은 의미의 다른 표현 | 정답 IR | 표현 일반화 |
| A-복합 | 여러 제약·알고리즘 요청 | 정답 IR | 순서·조건 보존 |
| E2E-미학습 | 새로운 문제 계열 | 기대 입출력/검사 함수 | 실제 코딩 능력 |

데이터 생성은 **훈련 대상 파리가 아닌 검증 가능한 사람이 작성한 기준 과제/코드**로 하고, 원본 질문/정답/생성 방식을 기록한다. 평가 문항은 학습과 모델 선택에 사용하지 않는다.

### 6.2 누출 방지 원칙

- 변수명 치환만으로 만든 평가는 **표면 일반화**로만 보고.
- 같은 알고리즘의 의미 동등 표현들은 train/test에 분산하지 않고 **group split** 적용.
- 훈련 중 validation으로 하이퍼파라미터를 고르되 test는 최종 1회.
- 학습 때 정답 IR을 입력한 Fly-Code 점수와 추론 때 A가 만든 IR 점수를 명확히 분리.
- 출력을 외운 모델을 걸러내기 위해 **미지의 숫자/식별자/리스트 길이/조건 조합** 평가.
- 코드 정답성은 AST 문자열 일치만이 아니라 **동일 동작의 여러 구현 허용**.
- 학습·검증 데이터 출처, 샘플 중복, 정답 오타, 실행 불가능한 과제 점검.

### 6.3 필수 지표

- **A/IR**: 정확한 IR 일치율, 연산 종류 정확도, 인자·복사 위치 정확도, 블록 구조 유효율, 의미 정확도.
- **B/Python**: 전체 토큰 일치율, 문법 통과율, 변수 참조 오류율, 실제 실행률, 단위 테스트 성공률.
- **E2E**: 요청별 Pass@1, Pass@3(재시도 수 분리), unseen algorithm Pass@1, 학습 전후 개선폭.
- **시냅스**: 변화한 시냅스 개수/비율, 변화량 분포, 구조 해시 고정, 학습 상태 복원 일치.
- **비용**: 단계별 실행 시간, CPU/RAM, 추론 시뮬레이션 스텝, 뉴런/간선 수.
- **정직한 판정**: 문법만 맞음/출력만 맞음/방법 제약 충족/완전 정답/검증 불가를 구분.

### 7.1 안전한 채점 환경

- **생성 코드에 메인 서버의 exec/eval 금지**. 기존 제한형 AST 해석기는 제한 범위의 빠른 검사에만 사용.
- 전체 Python 실행은 격리된 별도 프로세스/컨테이너에서 시행. 실행 시간·메모리·프로세스 수 제한, **네트워크 차단**, 읽기 전용 환경, 외부 파일/비밀키 접근 차단.
- OS 수준 격리가 없는 단순 subprocess timeout만으로는 완전한 샌드박스가 되지 않는다.
- 자동 시험 대상 코드의 import, I/O, subprocess 사용은 연구 목적에 필요한 경우에만 별도 허용.
- UI는 로컬 바인딩과 Origin 검사 외에도 향후 원격 공개 시 인증/권한/요청량 제한을 별도 설계.

- 작은 toy task에서 실제 시냅스 학습이 반복적으로 확인되지 않으면 **언어·코드 생성 단계 확장 보류**.

- 결과가 무작위 연결망과 동등하면 **FlyWire가 더 우수하다고 주장하지 않음**.

- 작은 데이터셋의 학습 전후/고정 가중치 대조 성능과 코드 실행 결과 공개.

- Fly-NL과 Fly-Code가 각자 독립 시냅스 학습을 수행.

- 컴파일만이 아니라 기능 테스트와 경계 사례를 통과하는 결과를 보고.

**연구 발표 가능한 완료 지점:**
- 실제 FlyWire / 무작위 재연결 / frozen / 한 파리 대조군을 동등 조건에서 비교.
- 최소 다중 시드 실험, 재현 가능한 명령/결과 파일/커밋/데이터 해시와 실패 사례 공개.
- **유의미한 개선이 없더라도** 한계를 명시한 결과와 원인 분석을 제공.
